| 4 TaskManagers | 32 | 4,281.06 msg/s | 22.19 ms | 59 ms | 335 ms | 49,803 | 0 | 22.05% / 95.84% | 0 |

多 TaskManager 在单台 8 vCPU VM 内没有带来吞吐收益，反而增加了进程、调度和 RPC 开销。当前场景建议默认使用单 TaskManager；只有在需要故障隔离或多作业资源隔离时再启用多 TaskManager。

## 10. 资源与 Checkpoint 汇总

汇总 34 个 VM 结果文件：

- CPU：各用例平均值的平均为 14.77%，用例内平均值最高 27.00%，全局峰值 96.23%。
- 内存：各用例平均值的平均为 4,636.27 MB，用例内平均值最高 5,539 MB，全局峰值 6,035.01 MB。
- 磁盘 I/O：各用例平均值的平均为 3.12 MB/s，用例内平均值最高 8.50 MB/s，全局峰值 333.30 MB/s。
- Checkpoint：累计完成 598 次、失败 3 次；加权平均耗时 8.41 ms，单次最大观测耗时 417 ms。
- 3 次 Checkpoint 失败分别出现在速率 1k、并发 5 作业和 p4@75k 重复第 1 次；均未演变为作业失败，长稳阶段 198/198 全部成功。

## 11. 结果评估

1. **正确性和可靠性良好**：小样本 100% 正确，长稳 1,080 万条零缺失；所有正式用例作业失败率和记录失败率均为 0，最终积压均清零。
2. **吞吐具有可扩展性但存在拐点**：并发作业从 1 增至 8 时吞吐由约 3.4k 增至 26.6k msg/s；4 个作业后 P95 从 11 ms 跃升至 386 ms，建议延迟敏感场景将并发上限控制在 2–4。
3. **多 TaskManager 当前不划算**：4 TM 相比 1 TM 吞吐略低、尾延迟更高、CPU 峰值更高；单台 VM 内优先采用 1 TM。
4. **高负载主要受 CPU 和 I/O 抖动影响**：CPU 峰值接近 96%，磁盘峰值达到 333 MB/s；若需要稳定 100k msg/s，建议增加 vCPU、提高数据盘 IOPS/带宽，并重新校准端到端速率。
5. **Checkpoint 总体稳定但需观察瞬时失败**：长稳无失败，但汇总仍有 3 次瞬时失败，建议后续保留 GC、Flink JobManager 和磁盘延迟日志，定位失败发生时的系统状态。
6. **执行异常已单独复核**：Kafka 日志恢复期间曾出现 2 次 Topic 创建超时，Flink 在长稳结束后曾停止；重试均成功，失败启动未生成正式结果，也未计入吞吐、失败率或积压统计。
